AgentMFA sandbox quickstart

Try every AgentMFA connection type against disposable local containers — no real credentials involved.

The sandbox starts four upstreams on 127.0.0.1: an authenticated HTTP API, a WebSocket echo, Postgres, and SSH. All credentials are fixed, fake test values; never reuse them anywhere else. AgentMFA itself runs natively on your machine.

1Check what you need

  • Docker with Compose v2 — running (start Docker Desktop first)
  • Node.js with npm
  • The AgentMFA app (or the headless broker, cargo run -p agentmfa-cli -- serve)

2Start the sandbox

git clone https://github.com/aka-com/agentmfa.git
cd agentmfa
npm run sandbox:up

The first start compiles the test fixture inside Docker and can take several minutes; later starts take seconds. When everything is ready it prints ready for HTTP, WebSocket, Postgres, and SSH, followed by the exact values to enter in AgentMFA. Re-print them any time with npm run sandbox:status.

3Add the four services in AgentMFA

Open AgentMFA from the menu bar icon; Services is the first tab, with an Add a service for your agent card at the top. (If the card isn't shown, re-enable it from the Walkthroughs menu — the ? button in the Services header — or use ＋ Add service to fill the form by hand.)

For HTTP API and WebSocket, use ＋ Add service and enter the printed fields manually. For Postgres and SSH, paste the Quick setup line into the card and press Continue — the service type is detected automatically and the form opens pre-filled. Enter any remaining values, press Add service, then press Test on the service's card in the list. Postgres TLS mode and the SSH Host key fingerprint are under the form's Advanced section. With the default ports:

TypeSetupThen
HTTP API Enter API root http://127.0.0.1:18080 manually Name sandbox-http · Bearer token agentmfa-test-token
WebSocket Enter URL ws://127.0.0.1:18081/ws manually Name sandbox-websocket · Bearer token agentmfa-ws-test-token
Postgres Quick setup: postgres://agentmfa:agentmfa-test-password@127.0.0.1:15432/agentmfa_sandbox?sslmode=disable Name sandbox-postgres; everything else pre-fills (TLS mode Disable, under Advanced)
SSH Quick setup: ssh -i <printed key path> -p 12222 sandbox@127.0.0.1
copy the exact line from sandbox:status — it carries the generated key's absolute path

Press Test on each service's card and expect:

sandbox-http — an authenticated HTTP 200
sandbox-websocket — WebSocket handshake succeeded
sandbox-postgres — Signed in to agentmfa_sandbox as agentmfa
sandbox-ssh — Key loaded; 127.0.0.1:12222 answered with SSH-2.0-… (reachability only; a real agent connection tests login)

4Let your agent use them

Pair an agent using the Connect an agent walkthrough, then ask it in plain language, for example:

  • “Using my AgentMFA service sandbox-http, make a GET request to /authenticated and summarize the response.”
  • “Using my AgentMFA service sandbox-postgres, run SELECT current_user, current_database();”
  • “Using my AgentMFA service sandbox-ssh, run uname -a on the server.”
  • “Using my AgentMFA service sandbox-websocket, connect and echo a message.”

Approve the prompts AgentMFA raises — reads (GET/HEAD) can get a read-scoped session, while POST, Postgres, SSH, and WebSocket opens need full access. The agent never sees the tokens, password, or key: check the Activity tab afterwards to watch every brokered call, with no secret values anywhere.

The API fixture also serves deterministic routes for deeper checks (redirects, binary and oversized bodies, arbitrary status codes) — see dev/sandbox/README.md.

5Stop or reset

npm run sandbox:down    # stop; keeps the generated SSH identities
npm run sandbox:reset   # delete containers, volumes, and SSH identities

After a reset the SSH fingerprint changes — run npm run sandbox:up again and update sandbox-ssh before reconnecting.

If something goes wrong

  • “cannot reach the Docker daemon” — start Docker Desktop and rerun npm run sandbox:up.
  • Port already in use — export SANDBOX_HTTP_PORT, SANDBOX_WS_PORT, SANDBOX_PG_PORT, or SANDBOX_SSH_PORT with a free port, then rerun. Keep the variables exported so sandbox:status prints matching values.
  • Anything else — docker compose -f dev/sandbox/compose.yaml logs, and the troubleshooting section of dev/sandbox/README.md.
